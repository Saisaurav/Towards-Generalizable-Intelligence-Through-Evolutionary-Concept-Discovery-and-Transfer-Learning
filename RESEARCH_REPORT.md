# Research report: repair, validation and transfer experiments

All numbers below come from raw JSON in `results_v2/` (one file per run, failures kept) and are regenerated by the scripts in `experiments/`.
Hardware: one CPU core. 10 seeds (11,22,33,44,55,66,77,88,99,111) per condition. Budget = 150,000 **PPO rollout steps** per seed
(evaluation steps used for fitness are logged separately in each run's `eval_steps`). Final scores use 1,000 held-out episodes on seeds disjoint
from training. "Greedy" = argmax over legal actions; "stochastic" = sampling from the policy (what evolution's fitness uses). Both are stored.
Several early runs carry a `-dirty` repo version because they were run before the corresponding commit.

## B. Architecture audit

**Existing and working (verified):** hidden layer built from `mlp_hidden`; forward pass matches a hand-computed reference (|diff| 4e-8); analytic
gradients through the hidden layer match finite differences (worst relative error 4.7e-4); PPO changes all 82/82 weights of an initial genome
(48/48 into hidden units); Lamarckian write-back persists them; Darwinian mode leaves weights untouched; clones and crossover of trained genomes keep trained weights exactly;
add-node mutation still grows the hidden layer. Target networks are trained from scratch in every run (a new `Population` per run); only expression strings carry over.

**Bugs / confounds found and what changed**

| Finding | Evidence | Change |
|---|---|---|
| Initial MLP genomes shared no history: each got its own hidden-node ids/innovations, so crossover could not align genes and speciation was degenerate | 0/16 shared hidden ids, 2/82 shared innovations, distance 2.00 | `make_mlp` now assigns hidden ids by (layer, unit): 16/16 and 82/82 shared, distance 0.20. Regression test added |
| Budget counted evaluation steps with PPO steps; a good CartPole policy spends most of the budget on evaluation | `steps` summed both | `train_steps`/`eval_steps` counted separately; runner budgets PPO steps only |
| Population 24 + 150k steps = ~12 generations, so any lineage gets only ~6k PPO steps | measured | population size swept (Stage 4) |
| `ConceptEnv` forces every game into per-action mode, which cripples CartPole | native 2-logit head: length 476; per-action `action_norm`: 107 | both representations reported; transfer uses the per-action wrapper |
| Scalar Nim state makes mod-4 structure very hard; learner collapsed to a constant policy | plateau +0.25 across all settings = "always take 3" (+0.248) | one-hot state diagnostic (labelled) reaches +0.78 |
| `load_compatible_concepts` trusted stored std metadata, did not evaluate | code inspection | now measures outputs on probe states (see E) |
| Stochastic held-out score hides learning (policies stay high entropy) | e.g. Connect Four greedy +0.61 vs stochastic +0.01 | both reported everywhere |
| My own harness bug: result cache keyed by tag+seed only (games shared files) | identical rows across games | caught before use; cache key now includes game; all affected runs deleted and rerun |

## D. Transfer experiment report (`results_v2/transfer_analysis.json`, `experiments/analyze_transfer.py`)

Setup: pop 6, 150k PPO steps, per-action `ConceptEnv` wrapper for every condition, 10 seeds, target trained from scratch each time. Concept sets (K=4):
`source` = shortlist of GP concepts discovered only on the source game (not filtered by target performance); `random` = 4 random trees per seed with the same primitives/admission filter
(depth ≤5, target std ≥0.01); `sxa` = `state_i × action_norm` features (4 evenly spaced state dims; Nim has only 1 state dim, so 1 feature); `target_trained` = GP discovered on the target game itself.
"Source concepts with no adaptation" is identical to `source`: this architecture has no adaptation step.

**Tic-Tac-Toe → CartPole** (held-out greedy episode length; AUC = mean held-out score over training)

| Condition | Final mean ± sd | median | worst / best | AUC | seeds reaching 450 |
|---|---|---|---|---|---|
| scratch | 333.5 ± 98.0 | 313.7 | 192 / 477 | 185 | 4/10 |
| **source concepts** | 283.3 ± 149.2 | 213.0 | 141 / 500 | 177 | 5/10 |
| random concepts | 294.6 ± 144.4 | 297.8 | 126 / 500 | 184 | 4/10 |
| raw state×action | 477.1 ± 45.4 | 500 | 381 / 500 | 421 | 10/10 |
| target-trained GP | 500.0 ± 0.0 | 500 | 500 / 500 | 500 | 10/10 |

Source vs scratch: −50 (95% bootstrap CI −145 to +53, permutation p=0.38). Source vs random: −11 (p=0.86). Source vs raw state×action: −194 (CI −277 to −104, p=0.002).
**Source concepts did not improve learning.** The benefit of `sxa` and target-trained concepts is real (p≤0.001) but shows that the *extra input features* matter, not cross-game transfer.
Target-trained concepts include `state_boundary_margin`, a CartPole-specific primitive unavailable to the source game.

**Connect Four → Nim:** all five conditions end at the identical constant "take 3" policy (+0.251 ± 0.039 in every condition, differences exactly 0). This pair is **uninformative**: the target learner never learns Nim under this representation, so there is nothing for concepts to improve.
(Concept output std on Nim: source 0.23–0.40, so the features were non-constant; the learner simply did not use them to learn.)

Computational cost: scratch 2.1 s/run, source 6.2 s, sxa 3.4 s, target-trained 10.7 s on CartPole. Not run: transfer on the Nim one-hot-state variant (it changes the observation, so concept primitives would differ), and larger budgets.

## E. Concept bank (`results/concept_bank.json`, v3; old bank kept at `results/concept_bank_v1_backup.json`)

- `load_compatible_concepts` now **measures** each concept on probe grid states (`probe_primitive_sets`) and rejects: malformed/unsupported formulas, unavailable primitives, unsupported contracts, a declared state dimension that differs from the target's,
  evaluation errors, any non-finite raw output, measured output std < 0.01, an invalid or <0.01 stored std, and duplicates. A bad entry is rejected with a reason (`screen_concepts`), not fatal. 10 tests in `test_concept_bank.py` cover constant, near-constant, non-finite, missing-primitive, valid, malformed and wrong-dimension cases; the old platform test was updated because missing stored std is no longer a rejection reason (outputs are measured instead).
- Regenerated bank: 8 concepts (4 TTT-sourced, 4 Connect Four-sourced), discovered with seed 2026 (pop 100, 30 generations; ~100 s each). Each stores formula, source environment, primitive dependencies, target and grid-probe output std, discovery fitness, validation/test |r|, pair-level transfer result, discovery seed and creation time.
- **Are they non-trivial?** Non-constant: yes (target std 0.18–0.40). Predictive: weakly. Held-out source |r| is 0.03–0.20, and two concepts (`state_max_abs`, `state_magnitude`) are single primitives with ~0 correlation to the source label. None were admitted (`admitted_into_target: false`) because they gave no measured benefit.
- Transfer performance is recorded at pair level only; per-concept ablations were not run.

## H. Final assessment

1. **Can the architecture learn individual games competently?** Partly. CartPole yes under the native 2-logit head (greedy), not under the per-action wrapper or with a stochastic policy. TTT reaches 0.88 win-or-draw without tactical features (target 0.90), 0.99 with them. Connect Four beats random but loses to a simple strategic opponent. Nim is learned only with a one-hot state encoding.
2. **Does Lamarckian inheritance work with hidden layers?** Yes, verified by tests (82/82 weights changed, persisted, inherited). Whether it beats Darwinian mode was not re-tested here.
3. **Does the concept generator discover non-trivial concepts?** Non-constant, yes; useful, no evidence: weak predictive correlation, two are bare primitives.
4. **Do source concepts improve target learning?** No: TTT→CartPole −50 length (p=0.38); Connect Four→Nim 0 (floor effect).
5. **Concept transfer vs random features?** No difference (−11, p=0.86).
6. **vs raw state-action expansion?** Worse: −194 (p=0.002).
7. **Which pairs work?** Neither.
8. **Unproven:** any positive cross-game transfer; transfer on a learnable Nim; effects at other budgets/populations; per-concept contributions; whether richer primitives (raw state, not just aggregates) would transfer; Lamarckian vs Darwinian under the corrected genome init; arbitrary game generation (only the grid-parameter contract exists).

## I. Learner fix follow-up (added after the first report; raw runs in `results_v2/learner_fix/`, rows also in `STANDALONE_REPORT.md`)

Changes (each tested on its own against the previous baseline, 10 seeds, 150k PPO steps):
1. **One-hot action identity inside `ConceptEnv`** (`act_onehot=1`; concepts still computed from the raw state).
2. **One-hot state encoding for 1-D integer states** (`state_onehot=22`, Nim only; concept primitives still use the raw scalar). It is a generic encoding, not a strategy.
3. **Greedy fitness evaluation** (`greedy_eval=1`): fitness episodes take argmax over legal actions instead of sampling.
4. **Population/PPO budget split:** pop 3 with 4 PPO iterations per genome per generation.

Standard config = all four, hidden 16, eval 10 episodes. Selected on seeds 11–111, then **confirmed on 10 fresh seeds 201–210** (never used for tuning):

| Game (wrapper, 150k steps) | Tuning seeds | Fresh seeds | Reference |
|---|---|---|---|
| CartPole length | 479 (500-rate 0.89) | **499.6 (500-rate 0.99)**; stochastic policy 166 | random 22 |
| Tic-Tac-Toe, no tactical features | return +0.72, win-or-draw 0.88 | return +0.74, **win-or-draw 0.90** (min 0.88) | optimum +0.96 / 0.996 |
| Connect Four | +0.79, win-or-draw 0.90 | +0.77, 0.89; vs strategic opponent −0.86 | |
| Nim (one-hot state) | +0.85, win rate 0.92 | +0.85, win rate 0.93 (min 0.89) | optimum +0.99; vs optimal opponent −0.80 |

Single-variable evidence along the way (tuning seeds): CartPole wrapper `action_norm` only 333 (pop 6) → +one-hot action 349 → pop 3 408 → pop 3 with 4 iterations 439 → +greedy fitness 479; pop 24 got *worse* (86). Greedy fitness alone gave small gains on TTT/Connect Four/Nim (+0.01 to +0.03), within seed noise.
TTT at 150k is budget-limited: the same config at 450k steps reaches win-or-draw 0.94 (min 0.92); that run is a diagnostic, not the transfer budget.

Caveats: TTT meets 0.90 only on the fresh seeds (0.88 on the tuning seeds), so it sits at the threshold; the stochastic CartPole policy still does not reach 500; Connect Four still loses to a simple strategic opponent, so it is not proficient; Nim is learned only with the one-hot state encoding. Whether Lamarckian write-back beats Darwinian under this config was not tested.
The transfer matrix in section D predates this fix and was run with `action_norm` only; it needs to be rerun with the standard config (concept sets, controls and seeds unchanged) before any updated transfer claim.

## J. v9 concept generator merged with the audited learner (raw runs: `results_v9/`; analysis: `results_v9/transfer_analysis.json`)

**Merge.** v9 left the learner core (`neat.h`, `ppo.h`, `genome.h`) identical to the original upload, so it lacked the fixes above. The two lines were merged with git (5 conflicts resolved). v9 contributes the `generic_state_action_v7` contract (33 primitives: distribution statistics, positional moments, transition deltas, board primitives for TTT/Connect Four only, unary operators) and the `--teacher-policy oracle` mode (exact minimax/recursion labels for TTT, Nim, LineWorld). The audited side contributes the hidden-layer init fix, step accounting, `runner`, one-hot options, measured concept screening (extended to the v7 primitives via a shared `_state_primitives` helper) and the research page. One v9 test was changed: `sqrt(neg(state_min))` is exactly constant on grid states, so it is now rejected by the measured screen. v9 also adds an `openai` dependency.

**Setup.** v9 discovery, seed 2026, pop 100, 30 generations, for TTT→CartPole and TTT→Connect Four (rollout and oracle teachers), Connect Four→Nim (rollout; Connect Four has no oracle), plus target-trained controls. Learner: the standard config from section I (pop 3, 4 PPO iterations, greedy fitness, one-hot action; one-hot state for Nim), 150k PPO steps, 10 seeds (11…111), target trained from scratch every run. Random controls draw 4 trees per seed from the same v7 vocabulary available in the target with the same admission filter; `sxa` = state×action features with the same one-hot options. 170 runs, 0 failures. Analysis: unpaired permutation tests and bootstrap CIs on the difference of means; Holm correction over the 8 source-vs-baseline comparisons.

|---|---|---|---|---|---|---|

Source vs scratch: CartPole rollout −68 (p=0.30), oracle +20 (p=0.60); Connect Four rollout +0.005 (p=0.76), oracle +0.013 (p=0.37); Nim +0.010 (p=0.76). All Holm-adjusted p = 1.0. **Conclusions.**
- v9 source concepts did not improve target learning over scratch, random v7 features or raw state×action on any of the three pairs, with either teacher. This includes TTT→Connect Four, the pair where board primitives exist in both games.
- Oracle labels gave somewhat more predictive source concepts (held-out |r| about 0.05–0.26 vs 0.00–0.20 for rollout) and the lowest CartPole variance (499 ± 2), but its early-training AUC was lower than scratch (305 vs 385) and no difference is statistically supported.
- Headroom limits what this test can show: with the audited learner, scratch already reaches 479/500 on CartPole, and Connect Four sits at ≈0.79 under every condition. Only Nim leaves room, and there only target-trained concepts helped.
- Not tested: low-budget regimes (v9's own pilot used 1,200-step learners, where concepts might matter more), several GP seeds, per-concept ablations, and larger primitive sets for Nim-like arithmetic structure. The oracle teacher is privileged supervision (perfect-play labels) on the source side and should be described that way.
- Bank v4 (`results/concept_bank.json`, 20 concepts, v7 contract, none admitted; 12 pass the grid-game screen, the rest depend on board primitives or duplicate another); v3 is kept at `results/concept_bank_v3_audit.json`.

## K. Why v9 concepts did not help, and what changed that (positive control, v8 vocabulary; raw runs `results_v9/positive_control/`, `results_v8/`)

**Diagnosis.** The v7 board primitives describe the *position*; they take the same value for every legal move, so a per-action scorer cannot use them to choose a move. A positive control with action-specific tactics ("this move wins now", "this move blocks the opponent's win"; hand-supplied, `repr=tactics`) lifts the standard learner on Tic-Tac-Toe from +0.74 to +0.925 (win-or-draw 0.99; vs the strategic opponent −0.43 → +0.15) and on Connect Four from +0.79 to +0.977 (vs strategic −0.86 → +0.39), so the harness can detect a concept benefit. Feeding the v7 position-level tactic primitives directly gave no gain (TTT +0.72, Connect Four +0.81).

**Change.** Two action-conditioned primitives, `action_wins_now` and `action_blocks_opponent` (contract `generic_state_action_v8`, available for TTT and Connect Four), were added to the Python generator, the C++ runtime and the platform policy. They are *supplied game knowledge* (afterstate lookahead for line-completion games); only their combination is discovered. Python and C++ agree on 807 (state, action) pairs with 0 mismatches (`test_action_primitives.py`; 56 Python tests pass).

**Discovery.** Same budget and seed as before (pop 100, 30 generations, seed 2026). Shortlisted concepts now use the new primitives, and held-out source |r| rises to 0.05–0.52 (rollout 0.42/0.37, oracle 0.52 for the best ones; previously ≤0.26).

**What this does and does not show.**
- A concept set discovered only on Tic-Tac-Toe, with no policy or weights carried over, makes Connect Four learning far better than scratch or matched random features, and as good as concepts discovered on Connect Four itself. In that narrow sense cross-game concept transfer is demonstrated for this pair.
- The gain is attributable to the two supplied primitives. Exposing them with no GP gives the same or slightly better result, so discovery adds nothing measurable beyond the vocabulary. The contribution is a vocabulary result (action-conditioned lookahead), not evidence that GP discovers useful structure on its own.
- Random trees over the same vocabulary recover about half of the gain (0.895) because they sometimes draw the primitives.
- Only one pair, one discovery seed, one budget (150k). Not tested: low-budget curves, other pairs (CartPole and Nim have no action primitives), per-concept ablations, selection by learning benefit, redundancy penalties, multi-game concepts.
- Bank v5 (`results/concept_bank.json`, 28 concepts): the 8 v8 concepts are marked `admitted_with_caveat` for Connect Four; the 20 v4 concepts stay not admitted.
